# План 1 из 7: каркас проекта — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Рабочий монорепозиторий: FastAPI-backend с конфигурацией, единым форматом ошибок, логированием, health-checks, таблицей `users` и CLI `create-tutor`; Next.js-frontend с генерируемым API-клиентом; Docker Compose для разработки; CI с линтерами и тестами.

**Architecture:** Модульный монолит на FastAPI (`app/core` — инфраструктура, `app/auth` — пользователи). Приложение собирается фабрикой `create_app(settings)`, ресурсы (engine БД, клиент Redis) создаются в lifespan и лежат в `app.state`. Frontend — Next.js App Router; API-клиент генерируется orval из OpenAPI-схемы, которую выгружает CLI backend.

**Tech Stack:** Python 3.12, uv, FastAPI, SQLAlchemy 2.0 async + asyncpg, Alembic, Pydantic v2 + pydantic-settings, redis-py (asyncio), structlog, argon2-cffi, email-validator, uuid-utils, typer; pytest, pytest-asyncio, pytest-cov, testcontainers, asgi-lifespan, httpx; Next.js 16, React 19, TypeScript, Tailwind, shadcn/ui, TanStack Query, zod, orval, Vitest, Testing Library; Docker Compose, just, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-11-english-tutor-mvp-design.md` (разделы 2, 3.1 — только `users`, 4.6, 6.3, 6.5, 7.1, 8.1, 8.2, 9 п.1)

**Серия планов:** 1 — каркас (этот), 2 — `auth` + `families`, 3 — `site_content` + лендинг, 4 — `leads` + `notifications` + мини-CRM, 5 — `lessons`, 6 — запросы на перенос/отмену, 7 — production. Каждый следующий план пишется после завершения предыдущего.

## Global Constraints

- Python 3.12 (`.python-version`, образ `python:3.12-slim`); Node.js 22 (`node:22-alpine`); PostgreSQL 16 (`postgres:16-alpine`); Redis 7 (`redis:7-alpine`).
- Все пути API начинаются с `/api`; OpenAPI — `/api/openapi.json`, Swagger — `/api/docs` (отключён при `APP_ENV=prod`).
- Первичные ключи — UUIDv7; у каждой таблицы `created_at`, `updated_at`; время — `timestamptz` (UTC).
- Формат ошибки: `{"error": {"code": str, "message": str, "details": object}}`; Pydantic-валидация → 422 `validation_error`; непредвиденная → 500 `internal_error` + `request_id`.
- Логи — JSON через structlog; заголовок `X-Request-ID` сквозной.
- Секреты только через переменные окружения / `.env`; в репозитории `.env.example`; pydantic-settings падает на старте без обязательной переменной.
- Образы запускаются не от root; backend — многоэтапная сборка на `python:3.12-slim` + uv; frontend — Next `output: "standalone"`.
- Python: `ruff check`, `ruff format`, `mypy --strict` без ошибок; покрытие `backend/app` ≥ 85%.
- Frontend: `eslint`, `tsc --noEmit`, `vitest` без ошибок; сгенерированный API-клиент коммитится.
- Тексты для пользователя (сообщения ошибок, CLI, UI) — на русском; идентификаторы и коды ошибок — на английском.
- Коммиты заканчиваются строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Несуществующий путь или неверный метод** (`GET /api/nope`, `DELETE /api/health`) — клиент ждёт тот же формат `{"error": {"code": "not_found" | "method_not_allowed"}}`, а не стандартный `{"detail": ...}` Starlette. Тест в Task 2.
2. **Мусорный `X-Request-ID` от клиента** (переводы строк, 500 символов) — не должен попадать в логи и ответ как есть; заменяется сгенерированным. Тест в Task 3.
3. **БД или Redis недоступны** — приложение всё равно стартует, `/api/health` отвечает 200, `/api/health/ready` за ≤ 3 с отвечает 503 с указанием, что упало, а не висит и не падает. Тест в Task 4.

### Task 3: Request ID, структурированные логи, обработка 500

**Files:**
- Create: `backend/app/core/request_id.py`, `backend/app/core/logging.py`, `backend/tests/core/test_request_id.py`
- Modify: `backend/app/main.py` (вызов `configure_logging`, подключение middleware)

**Interfaces:**
- Consumes: `error_body` (Task 2), `Settings.log_level`, `Settings.log_json` (Task 1).
- Produces:
  - `app.core.request_id.REQUEST_ID_HEADER = "X-Request-ID"`, `get_request_id() -> str | None` (из `ContextVar`).
  - `app.core.request_id.RequestIdMiddleware` — чистый ASGI-middleware (не `BaseHTTPMiddleware`). Принимает входящий заголовок, если он совпадает с `^[A-Za-z0-9._-]{1,64}$`, иначе генерирует `uuid4().hex`; кладёт в `ContextVar` и `structlog.contextvars`; добавляет заголовок к **любому** ответу. Непойманное исключение из приложения логирует (`log.exception("unhandled_error")`) и само отвечает `500` с `error_body("internal_error", "Внутренняя ошибка сервера", {"request_id": rid})` и заголовком `X-Request-ID`. После ответа пишет одну строку access-лога `http_request` с полями `method`, `path`, `status`, `duration_ms`.
  - `app.core.logging.configure_logging(level: str, json: bool) -> None` — structlog + stdlib logging, процессоры: `merge_contextvars`, `add_log_level`, `TimeStamper(fmt="iso", utc=True)`, `format_exc_info`, затем `JSONRenderer()` или `ConsoleRenderer()`; вывод в `sys.stdout`. Логгеры `uvicorn.access` отключены.

async def test_access_log_contains_request_id(client, capsys):

**Files:**
- Create: `frontend/orval.config.ts`, `frontend/src/lib/api-fetch.ts`, `frontend/src/lib/api-fetch.test.ts`, `frontend/openapi.json`, `frontend/src/api/generated/**`
- Modify: `frontend/package.json`, `justfile`, `frontend/eslint.config.mjs` (игнор `src/api/generated/**`)

**Interfaces:**
- Consumes: `python -m app.cli export-openapi PATH` (Task 6).
- Produces:
  - `src/lib/api-fetch.ts`:
    - `class ApiError extends Error { readonly status: number; readonly code: string; readonly details: Record<string, unknown>; readonly requestId: string | null }`.
    - `apiFetch<T>(url: string, init?: RequestInit): Promise<T>` — orval-mutator. `credentials: "same-origin"`, заголовок `Accept: application/json`. `2xx` → JSON (для `204` — `undefined as T`). Не-`2xx` с телом `{"error": {...}}` → `ApiError(status, code, message, details)`. Не-`2xx` без такого тела → `ApiError` с `code: "unknown_error"`, `message: "Сервер вернул ошибку " + status`. Отказ `fetch` → `ApiError` с `status: 0`, `code: "network_error"`, `message: "Нет соединения с сервером"`. `requestId` — из заголовка `X-Request-ID` ответа.
  - `orval.config.ts` — два выхода из `./openapi.json`:
    - `api`: `client: "react-query"`, `httpClient: "fetch"`, `mode: "tags-split"`, `target: "src/api/generated/endpoints"`, `schemas: "src/api/generated/model"`, `override.mutator: { path: "src/lib/api-fetch.ts", name: "apiFetch" }`;
    - `zod`: `client: "zod"`, `target: "src/api/generated/zod"`.
  - Рецепт `gen-api`: `uv --directory backend run python -m app.cli export-openapi ../frontend/openapi.json`, затем `pnpm --dir frontend gen:api`.
