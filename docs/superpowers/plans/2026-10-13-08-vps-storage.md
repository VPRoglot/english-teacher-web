# План 8: хранилище на VPS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** В production фото лендинга хранятся в MinIO на том же VPS, а не у внешнего S3-провайдера. Стек полностью запускается без бэкапов, но всё нужное для бэкапов остаётся в проекте и включается профилем.

**Architecture:**
- **Хранилище.** В `infra/docker-compose.prod.yml` появляются `minio` и одноразовый `minio-init`. Логика init вынесена в `infra/minio/init.sh`, чтобы её можно было протестировать.
  - `minio-init` создаёт бакет и включает анонимное чтение;
  - заводит пользователя приложения с политикой «только этот бакет».
- **Конфигурация.** api получает адрес MinIO из prod-оверлея, nginx проксирует `/media/` на MinIO внутри сети Docker.
- **Бэкапы.** Сервис `backup` уходит в профиль `backup`, а его обязательные переменные перестают ломать интерполяцию compose, когда профиль выключен.
- **E2E.** Стек использует MinIO из prod-оверлея; добавляется сценарий с загрузкой фото.

**Tech Stack:** без новых зависимостей; образы `cgr.dev/chainguard/minio` и `minio-client` (уже закреплены по digest в dev и e2e).

**Spec:** `docs/superpowers/specs/2026-10-13-vps-storage-design.md` (дополнение к `docs/superpowers/specs/2026-10-11-english-tutor-mvp-design.md`).

**Предыдущие планы:** 1–7 выполнены, код в `main`. Журнал плана 7: `docs/superpowers/ledgers/2026-10-13-07-production.md`. Правила оттуда действуют:
- `migrate` в профиле, откат не трогает схему;
- e2e изолирован от корневого `.env` через `env_file: !override [e2e.env]`;
- сторонние образы закреплены по digest.

## Global Constraints

- **Всё из планов 1–7 действует:**
  - shell — POSIX `sh` в alpine/chainguard-образах, `bash` для тестовых скриптов;
  - `set -eu`; LF, бит исполнения;
  - сторонние образы — `tag@sha256:…`;
  - рецепты `justfile` — одна команда на строку;
  - коммиты заканчиваются строкой `Co-Authored-By: <модель> <noreply@anthropic.com>`.
- **Спека 3.1:**
  - root-учётку (`MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`) получают только `minio` и `minio-init`;
  - приложение работает под `S3_ACCESS_KEY` / `S3_SECRET_KEY` с правами только на `${S3_BUCKET}`.
- **Спека 3.1:** у `minio` портов наружу нет, том `miniodata`, `restart: unless-stopped`, логи json-file 10m×5, лимит памяти 512 МБ.
- **Спека 3.1:** от `minio-init` (`service_completed_successfully`) зависит только api; worker и scheduler от него не зависят.
- **Спека 3.2:**
  - prod-compose задаёт `S3_ENDPOINT_URL=http://minio:9000`, `S3_ADDRESSING_STYLE=path`, `MEDIA_UPSTREAM=http://minio:9000/${S3_BUCKET}`, `MEDIA_UPSTREAM_HOST=minio:9000`;
  - в `prod.env.example` этих строк больше нет;
  - `BACKUP_*` и `HEARTBEAT_BACKUP_URL` закомментированы.
- **Стек без бэкапов** — в `.env` нет ни одной `BACKUP_*`:
  - `docker compose … config` и `up` проходят;
  - `backup` не входит в граф `up` без `--profile backup`.
- **Текст политики конфиденциальности дословно:** «Если ведутся резервные копии, удалённые данные исчезают из них не позднее чем через 6 месяцев.»

## Review Focus

1. **Повторный `up` и деплой.** `minio-init` запускается при каждом `up`, поэтому второй и следующие запуски должны проходить с кодом 0: пользователь уже есть, политика уже привязана, бакет уже есть. Тест в Task 1 (init дважды).
2. **Смена `S3_SECRET_KEY` в `.env`.** После следующего `up` приложение работает с новым паролем, старый больше не действует. Тест в Task 1.
3. **Права приложения.** Учётка приложения может писать и читать в `${S3_BUCKET}`, но не может:
   - создать или удалить другой бакет;
   - писать в другой бакет;
   - выполнять admin-операции.
   
   Тест в Task 1.
4. **Свежий сервер без переменных бэкапа.** `.env` без `BACKUP_*` → `config` и `up` проходят. Сейчас там `${BACKUP_S3_BUCKET:?…}`, а compose ругается на это даже при выключенном профиле. Тест в Task 2 (CI-шаг).
5. **Фото переживает пересоздание контейнера** (деплой пересоздаёт `minio`): объект, загруженный до рестарта, читается после него. Тест в Task 1.
