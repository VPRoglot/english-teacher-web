# План 5 из 7: `lessons` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Репетитор ведёт расписание: настройки (часовой пояс, порог поздней отмены), регулярные серии с материализацией на 8 недель, разовые и пробные занятия, заметки (общая и приватная). Расписание видно в календаре админки и в кабинете семьи.

**Architecture:**
- **Backend.** Новый модуль `app/lessons`:
  - модели `tutor_settings`, `lesson_series`, `lessons`, `lesson_notes`;
  - чистая функция развёртки RRULE (`recurrence.py`) и материализация серий (`generation.py`). Генерация движется только вперёд от «фронтира» серии `generated_through`;
  - админ-роутер (настройки, занятия, заметки, серии, пробные) и роутер кабинета;
  - ежедневная задача Taskiq по расписанию. Её запускает новый процесс `taskiq scheduler` — сервис `scheduler` в compose.
- **Зависимости модулей.** `lessons` зависит от `families` и `leads` только через их сервисы, обратных зависимостей нет. Поэтому серии не встраиваются в `GET /admin/families/{id}`, а заявка не отдаёт свои занятия.
- **Frontend.**
  - FullCalendar (MIT-плагины `daygrid`, `timegrid`, `list`, `interaction` + `luxon3` для именованного часового пояса) и luxon для пересчёта «дата и время в поясе репетитора ↔ UTC».
  - Страницы: `/admin/calendar`, `/admin/lessons/[id]`, `/admin/settings`, серии на `/admin/families/[id]`, «Назначить пробное» в карточке заявки, `/cabinet` (главная), `/cabinet/calendar`, `/cabinet/lessons/[id]`.

**Tech Stack:**
- Backend: как в плане 4, плюс `python-dateutil` (RRULE), `tzdata` (база часовых поясов для Windows и slim-образа), dev — `types-python-dateutil`. Планировщик — `taskiq.TaskiqScheduler` + `LabelScheduleSource` (уже в taskiq 0.13).
- Frontend: плюс `@fullcalendar/core`, `@fullcalendar/react`, `@fullcalendar/daygrid`, `@fullcalendar/timegrid`, `@fullcalendar/list`, `@fullcalendar/interaction`, `@fullcalendar/luxon3`, `luxon`, `@types/luxon`.

**Уточнения спеки, принятые в этом плане:**
1. **Фронтир генерации `lesson_series.generated_through date NULL`.**
   - Генерация создаёт занятия только для местных дат после фронтира, затем сдвигает его.
   - Без фронтира перенесённое (`is_detached`) или удалённое занятие серии ежедневная задача создала бы заново на старом месте: `UNIQUE (series_id, starts_at)` его уже не защищает.
   - `UNIQUE (series_id, starts_at)` + `ON CONFLICT DO NOTHING` остаются для идемпотентности повторов и гонок.
2. **Подмножество RRULE:**
   - только `FREQ=WEEKLY`, обязательный `BYDAY` (`MO`…`SU`) и необязательный `INTERVAL` 1–4;
   - `DTSTART`, `UNTIL`, `COUNT` запрещены: границы серии задают `starts_on` и `ends_on`;
   - правило хранится в каноническом виде, например `FREQ=WEEKLY;INTERVAL=2;BYDAY=TU,FR`.
   
   Чётность недель при `INTERVAL=2` отсчитывается от `starts_on`.
3. **Смена часового пояса в настройках** перегенерирует будущие (`starts_at > now`) занятия активных серий в статусе `scheduled` без `is_detached`. Они остаются в то же местное время, но в новом поясе. Разовые, пробные и отсоединённые занятия сохраняют свой момент времени.
4. **Ссылка на подключение.**
   - Серия копирует свой `meeting_url` в создаваемые занятия.
   - Эффективная ссылка `join_url` = `lesson.meeting_url`, если она задана, иначе `child.default_meeting_url`; у пробного — только `lesson.meeting_url`.
5. **Отложено до плана 6:**
   - условие «по которым нет запросов» для удаления занятия;
   - «активный запрос» в `GET /me/lessons/{id}`;
   - дашборд.
   
   Таблицы `change_requests` в плане 5 нет.
6. **Новые эндпоинты:**
   - `GET /me/schedule-settings` → `{timezone, cancel_policy_hours}` — пояс для кабинета; порог понадобится плану 6;
   - `GET /admin/leads/{id}/trial-lessons` — пробные занятия заявки для карточки.
   
   Серии семьи страница семьи читает через `GET /admin/series?child_id=` для каждого ребёнка.
7. **Правила `PATCH /admin/lessons/{id}`:**
   - `completed` и `no_show` — только для начавшегося занятия (`starts_at <= now`), иначе 409 `lesson_not_started`;
   - время, длительность и ссылку можно менять только у занятия в статусе `scheduled`, иначе 409 `lesson_not_editable`;
   - смена `starts_at` у занятия серии выставляет `is_detached = true`;
   - переход в любой другой статус, включая возврат в `scheduled`, разрешён.
8. **Диапазон запроса занятий:** `from < to` и `to - from ≤ 62` дня, иначе 422. Занятие попадает в диапазон по `starts_at ∈ [from, to)`.
9. **Длительность занятия** — от 15 до 240 минут; у пробного по умолчанию 30.
10. **Пересечения (`warnings`)** считаются с занятиями в статусах `scheduled`, `completed` и `no_show`; отменённые не мешают. Ответы `POST /admin/lessons`, `PATCH /admin/lessons/{id}`, `POST /admin/leads/{id}/trial`, `POST /admin/series` и `PATCH /admin/series/{id}` содержат `warnings` (не больше 20).
11. **Пробное занятие** назначается из статусов, откуда таблица переходов разрешает `trial_scheduled` (`new`, `contacted`). Перенести его можно правкой занятия. Отказ по заявке пробное не трогает.
12. **Ежедневная задача** пропускает архивные серии, серии с `ends_on` в прошлом и серии архивных детей и семей.
13. **Даты в админке** (заявки, семьи, ссылки) показываются в поясе репетитора, а не в зашитом `Europe/Moscow`: `formatMoscow` заменяется на `formatDateTime(iso, tz)`.

## Global Constraints

- **Всё из планов 1–4 действует:**
  - Python 3.12, префикс `/api`, UUIDv7, `timestamptz` в UTC;
  - единый формат ошибок, русские тексты;
  - ruff, mypy strict, eslint, tsc; покрытие ≥ 85%;
  - сессия БД только через `DbSession`, в worker — `state.sessionmaker`;
  - после изменения API — `just gen-api` и коммит `frontend/openapi.json` + `frontend/src/api/generated/**`;
  - имена обработчиков = operationId, роутеры импортируют сервисы модулем;
  - `/admin/*` для не-репетитора → 404, без сессии → 401;
  - задачи идемпотентны (повтор при ошибке включён для всех);
  - focused vitest: `pnpm --dir frontend exec vitest run <пути>`;
  - коммиты заканчиваются строкой `Co-Authored-By: <модель> <noreply@anthropic.com>`.
- **Модель данных** (спека 3.3, дословно, плюс уточнение 1):
  ```
  tutor_settings   singleton (id = 1): timezone (по умолчанию Europe/Moscow),
                   cancel_policy_hours (по умолчанию 24)
  lesson_series    id, child_id → children, rrule, local_start_time, duration_min,
                   meeting_url NULL, starts_on (date), ends_on NULL (date), archived_at
                   + generated_through NULL (date)
  lessons          id, series_id NULL → lesson_series, child_id NULL → children,
                   lead_id NULL → leads, kind (regular|trial), starts_at, duration_min,
                   meeting_url NULL, is_detached (bool, default false),
                   status (scheduled|completed|cancelled|cancelled_late|no_show)
                   CHECK: ровно одно из child_id / lead_id NOT NULL
                   CHECK: kind = trial ↔ lead_id NOT NULL
                   UNIQUE (series_id, starts_at)
  lesson_notes     lesson_id PK → lessons, shared_text (markdown), private_text (markdown)
  ```
- **Материализация:**
  - на 8 недель вперёд (`HORIZON_DAYS = 56`);
  - местное время переводится в UTC отдельно для каждой даты через `zoneinfo`;
  - при создании серии — синхронно;
  - ежедневно — задачей worker.
- **`scope=this_and_following`:**
  - меняет параметры серии с даты `from` и перегенерирует будущие занятия в статусе `scheduled` без `is_detached`;
  - прошедшие, отмеченные и отсоединённые занятия не трогаются;
  - серия разделяется: у старой выставляется `ends_on = from − 1 день`, создаётся новая.
- **Архивирование серии** удаляет её будущие занятия в статусе `scheduled` (кроме `is_detached`) и прекращает генерацию.
- **Удаление занятия:** только будущее и в статусе `scheduled`.
- **Права:**
  - `family_scope` определяет доступные `child_id`; объект вне области → 404;
  - ответы для семьи строятся из схем без `private_text`;
  - пробные занятия семье не видны.
- **Время во frontend:** все даты показываются в поясе репетитора; если пояс браузера другой, рядом с временем указывается пояс.
- **Заметки:** Markdown. В админке — textarea с предпросмотром; отрисовка — существующий `components/site/markdown.tsx` (без сырого HTML).
- **Календарь:** FullCalendar, только MIT-плагины. В админке — неделя и день; на мобильном — список. В кабинете — месяц и неделя на десктопе, список на мобильном (`< 768px`).

## Review Focus

1. **Летнее время и смена пояса.**
   - Серия «вт 10:00» в `Europe/Berlin` через переход 2026-03-29 остаётся в 10:00 по местному времени: 09:00 UTC до перехода, 08:00 UTC после.
   - Местное время, которого нет (02:30 в день перехода), даёт 03:30 по летнему времени, а не ошибку.
   - Смена пояса в настройках сохраняет местное время будущих занятий серий.
   
   Тесты в Task 2.
2. **Перенесённое или удалённое занятие серии не воскресает.** После переноса занятия на другое время (или удаления) повторный прогон материализации не создаёт занятие на старом месте. Тест в Task 2 (`test_moved_and_deleted_lessons_do_not_come_back`).
3. **Утечка между семьями и `private_text`.**
   - Родитель семьи A получает 404 на занятие семьи B.
   - Ребёнок не видит занятия брата или сестры.
   - Пробные занятия не видны в кабинете.
   - Ни в одном ответе `/me/*` нет `private_text`: проверяется по сырому JSON.
   
   Тесты в Task 6.
4. **Разделение серии.** Правка «с 20 октября» оставляет нетронутыми прошедшие, `completed`/`cancelled` и отсоединённые занятия. Будущие `scheduled` перегенерируются с новыми параметрами, у старой серии `ends_on = 19 октября`. `from` в прошлом → 422. Тесты в Task 4.
5. **Двойные действия и гонки.**
   - Двойной клик «Назначить пробное» → второй запрос 409 `invalid_status_transition`, пробное занятие одно (блокировка заявки `FOR UPDATE`).
   - Два прогона материализации подряд → ни одного дубля.
   - Перенос занятия серии на время другого занятия той же серии → 409 `lesson_slot_taken`, а не 500.
   
   Тесты в Task 5, Task 2, Task 3.

      - принимает любой регистр и пробелы вокруг `;`/`=`;
      - ключи только `FREQ`, `INTERVAL`, `BYDAY`; `FREQ=WEEKLY` обязателен; `BYDAY` — непустой список без повторов;

    - `occurrences(rule: str, *, starts_on: date, ends_on: date | None, local_time: time, tz: ZoneInfo, first_day: date, last_day: date) -> list[datetime]`:
      - возвращает моменты в UTC (aware) для местных дат в `[max(starts_on, first_day), min(ends_on, last_day)]`;
      - `dtstart = datetime.combine(starts_on, local_time)` — от него отсчитывается чётность недель;
      - каждая дата → `datetime.combine(d, local_time, tzinfo=tz).astimezone(UTC)` с `fold=0`: несуществующее время сдвигается вперёд, неоднозначное берёт первый вариант.

    - `HORIZON_DAYS = 56`;
    - `async def materialize_series(session, series: LessonSeries, *, tz: ZoneInfo, now: datetime) -> list[Lesson]`:
      - вызывающий держит блокировку серии;
      - `today = now.astimezone(tz).date()`;
      - диапазон дат: от `max(series.generated_through + 1 день, series.starts_on, today)` (без фронтира — без первого слагаемого) до `today + HORIZON_DAYS`;

      - вставка `INSERT … ON CONFLICT (series_id, starts_at) DO NOTHING RETURNING` с `kind=regular`, `child_id`, `duration_min`, `meeting_url` серии;
      - `series.generated_through = max(старый, today + HORIZON_DAYS)`;
      - возвращает только созданные занятия;
    - `async def regenerate_series_from(session, series, *, from_day: date, tz: ZoneInfo, now: datetime) -> list[Lesson]`:
      - удаляет занятия серии со `status = scheduled`, `is_detached = false`, `starts_at >= max(local_midnight(from_day, tz), now)`;
      - выставляет `generated_through = from_day − 1 день`;

    - `SeriesCreate`: `child_id`, `rrule: RRule`, `local_start_time: LocalTime`, `duration_min: DurationMin`, `meeting_url: MeetingUrl | None = None`, `starts_on: date`, `ends_on: date | None = None`; валидатор `ends_on >= starts_on` (ошибка на `ends_on`);
    - `SeriesUpdate`: те же поля без `child_id` и `starts_on`, все необязательны (`meeting_url` и `ends_on` можно сбросить в `null`);
    - `SeriesDetail`: `id`, `child_id`, `child_name`, `rrule`, `local_start_time`, `duration_min`, `meeting_url`, `starts_on`, `ends_on`, `archived_at`;
    - `SeriesSaved`: `series: SeriesDetail`, `lessons_created: int`, `warnings: list[OverlapWarning]`.
  - **Сервис (`app.lessons.series_service`):**
    - `list_series(session, *, child_id: UUID | None, include_archived: bool) -> list[SeriesDetail]` — сортировка по `starts_on`;
    - `create_series(session, data, *, now) -> SeriesSaved` — `get_active_child`, `materialize_series`, пересечения созданных занятий с остальными (`exclude_ids` = созданные);
    - `update_series(session, series_id, data, *, from_day: date, now) -> SeriesSaved`:
      - `SELECT … FOR UPDATE`; архивная серия → `SeriesArchived`;
      - `from_day` раньше сегодняшнего дня в поясе репетитора → 422 на `["query", "from"]` «Дата не может быть в прошлом»;
      - `from_day` позже `ends_on` → 422 на том же поле;
      - `from_day <= series.starts_on` → правка на месте и `regenerate_series_from(series, from_day=series.starts_on)`;
      - иначе разделение:
        1. старой серии ставится `ends_on = from_day − 1`;
        2. её занятия `scheduled`, без `is_detached`, начиная с местной полуночи `from_day` (и не раньше `now`), удаляются;
        3. создаётся новая серия: поля старой с изменениями из `data`, `starts_on = from_day`, `ends_on` — из `data`, если передано, иначе прежний `ends_on`;
        4. `materialize_series(новая)`;
      - возвращает итоговую серию — новую или изменённую;
    - `archive_series(session, series_id, *, now) -> None` — `archived_at = now` и удаление будущих (`starts_at > now`) занятий `scheduled` без `is_detached`. Повторное архивирование → `SeriesArchived`.
  - **Роутер:**
    - `GET /admin/series?child_id=&archived=false` → `list_series`;
    - `POST /admin/series` (201) → `create_series`;
